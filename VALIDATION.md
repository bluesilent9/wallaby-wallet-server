Validated 14 November 2026 with isolated invented wallets, keys and profiles. No live household profile, SSH permissions, wallet, service or Agent source was changed.

192 selected regression checks run: 189 passed; three optional integrations needing historical Agent snapshots were skipped. Eleven new tests reproduce both reported faults. Both public source offers appear without executable transfer proposals. The actual Agent Build 93 offer Store/table can deny and re-enable a discovered wallet before pairing without creating an approval or active transfer.

Checks preserve local/duplicate wallet exclusion, private/watch source distinctions, complete-destination absence checks, and rejection of failed/stale/reconnected partial sources. A new Agent completes the actual signed permission identity outbox, then registers in the relay directory without a Wallet Builder session. The saved signed identity passes profile archive validation. Changed keys, invalid signatures/hostnames, stale challenges and reconnects during signature verification cannot pin a new identity. Routine permission handshakes preserve existing Builder identity envelopes and challenges byte-for-byte; pairing remains required.

Related tests cover current encrypted relay, public offers, permission polling, immutable signed previews, delayed outcomes, Extinct history, retirement reconciliation, statement persistence, profile archives, diagram/ledger controls and foreground identity handling. The full historical suite and the user's live household reconnect were not tested here. Older integration harnesses requiring obsolete Agent APIs were not treated as current-Agent compatibility requirements.

Installer checks cover version/metadata, exact extracted-source parity, absence of runtime wallet/config/upload/log/PSBT files, and isolated IPv4/IPv6 browser and Agent health startup. The package is built but not installed on the user's server. No Agent protocol update, SSH-rule change, wallet recreation or profile reset is required. Discovery and identity bootstrap do not themselves pair Agents or authorise transfers.
