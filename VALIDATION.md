* **925 Python tests passed**, including 28 new authentication, encrypted-relay, migration, current-protocol and mobile-data tests. Existing Agent Build 65 source was read for the retained, already-pending request/result interoperability tests; no Agent source was changed. The older tests explicitly seed pre-upgrade invitations rather than enabling any new-production fallback.
* **53 JavaScript suites passed**. Python syntax checks and changed JavaScript syntax checks passed.
* Real browser: existing user enrollment through blinded OPAQUE messages, password confirmation, login, mobile pairing/revocation, no JavaScript errors. The anonymous chooser hides DOB, holdings, reports and ownership; the user-ID login shortcut and unauthenticated account/admin reads are rejected. Successful login rotates the browser workspace token.
* Real OPAQUE client/server exchanges: same password on independent devices after restart; wrong password, replay, cross-workspace proofs, expired setup, account overwrite and plaintext-password fields rejected. Registration is committed only after successful login. A profile export/import retained OPAQUE records and the unfinished transaction builder unchanged. A paired phone cannot read account data before password authentication or authenticate another user.
* Reference Noise 0.3.1 clients (test-only dependency, not part of production) completed a **Noise_IKpsk2_25519_ChaChaPoly_SHA256** handshake and sent ciphertext through the real Server relay object. Wrong pairing PSK, modified ciphertext and replay were rejected by the reference receivers. Relay state contained neither plaintext nor PSK. This validates the courier path and the selected primitive; it is not a security audit of future Agent/Mobile clients or their QR grants/application protocols.
* Relay controls require signed, role-bound registrations and fresh, one-use connection challenges. Both Agents must attest the same live handshake. Mobile-role attestations cannot satisfy an Agent mesh. Other recipients cannot acknowledge a frame. Duplicate retries are idempotent; changed bytes under an existing ID, extra plaintext fields and sender spoofing are rejected. Queues and receipts are bounded, expiring, memory-only and reset on profile replacement.
* New wallet sync v3 works without peer IP addresses and binds the signed public preview to actual peer identity/Noise public keys. No channel means no silent direct-SSH fallback for new invitations. Multisig setup v2 and refresh-policy v2 bind encrypted-peer requirements into immutable request hashes. Old clients without the new capability are withheld. Missing refresh mesh cannot allocate a new address or mutate the saved builder. In-flight pre-upgrade signed requests retain their original hashes.
* Mobile balance responses contain exact BTC/satoshis without market valuation, unrealised gain, quote or FX fields. Saved tax reports retain historical AUD tax figures while removing live balance sections. Quote fetching is prohibited in these read paths and tested with network lookup disabled.
* Installer audit: package metadata and Node.js dependency; runtime source parity; no runtime profiles, wallet files, logs, PDFs, ODS/CSV uploads or PSBTs; systemd identity and data migration; actual extracted IPv4/IPv6 browser and Agent health startup. Packaging does not install/start the service on this computer.

## Integration boundary

Only Server work is delivered here. The Agent and Mobile projects must implement [SECURE_RELAY.md](docs/SECURE_RELAY.md), [PASSWORD_AUTH.md](docs/PASSWORD_AUTH.md) and [MOBILE_DATA.md](docs/MOBILE_DATA.md). Their native QR pairing, protected device key/PSK storage, Noise/application state machines, signing-policy agreement and Android password interoperability require tests with their updated builds before using the new path with funds. No real Bitcoin transaction or physical archive burn was performed for this release.

OPAQUE does not make weak passwords safe from offline guessing after full server compromise. Server-delivered browser code can steal typed passwords if that code is compromised; a separately installed trusted app avoids that code-delivery dependency. A courier can always censor/delay traffic and sees routing metadata. These limits are documented rather than described as impossible attacks.
